# ITEM-0035: Implement cross-platform encryption interoperability tests

## Why

The claim "an envelope encrypted on iOS decrypts on Windows" is unverifiable without
committed test vectors that run identically on every platform. Unit tests on a single
platform only prove that one platform is self-consistent. Test vectors prove format
compatibility and catch any platform-specific encoding divergence before it reaches
production.

## Scope

- JSON test vector files in `test/vectors/`: fixed inputs, expected nonce (where
  deterministic), expected ciphertext, expected decrypted plaintext
- Test runner that loads the vector file and asserts each case
- Vectors covering: Argon2id hash verification, XChaCha20-Poly1305 round-trip, HKDF
  subkey derivation, EncryptedEnvelope round-trip, padding/unpadding
- CI job that runs the vector suite in Node.js and in a Hermes-compatible environment

## Out of scope

- Live network tests between physical devices
- UI automation tests
- Coverage thresholds

## Constraints

- Blocked by ITEM-0025 (pipeline must be implemented before vectors can be generated)
- Vectors must be generated from a reference run and then frozen; they are not
  regenerated automatically on every test run
- Any format change that breaks existing vectors is a migration event requiring a new
  vector file

## Decisions and rejected alternatives

- Chose committed JSON test vectors over a live cross-device RPC test harness because
  live tests require physical devices in CI, which is prohibitively fragile
- Rejected generating vectors dynamically in tests because dynamic generation masks
  format regressions; the vectors are the spec
