# ITEM-0015: Implement password hashing and verification with Argon2id

## Why

Password hashing is the first cryptographic primitive used during account creation
and login. A weak or incorrectly parameterised KDF (e.g., bcrypt with low cost,
PBKDF2 with low iterations) makes offline dictionary attacks feasible on a stolen
database. The server-stored verifier must be distinct from the encryption key derived
in ITEM-0018.

## Scope

- Implement `hashPassword(password: Uint8Array): Promise<PasswordVerifier>` using
  Argon2id with parameters from the selected library's recommended defaults
- Implement `verifyPassword(password, verifier): Promise<boolean>`
- Verifier format must encode: algorithm name, Argon2id m/t/p parameters, and the
  salt, so future parameter upgrades are detectable without breaking old verifiers
- Unit tests for the above acceptance criteria

## Out of scope

- The server endpoint that stores the verifier
- Key derivation from the password — that is ITEM-0018
- Parameter upgrade migration path (to be added as a separate story once upgrade is needed)

## Constraints

- Blocked by ITEM-0014 (interface must exist) and ITEM-0013 (library must be selected)
- Must use Argon2id specifically, not Argon2i or Argon2d
- PasswordVerifier must be opaque to the server (no key material embedded)

## Decisions and rejected alternatives

- Chose Argon2id over bcrypt and PBKDF2 because Argon2id won the Password Hashing
  Competition and provides both memory-hardness and side-channel resistance
- Rejected scrypt because the selected library evaluation (ITEM-0012) may show
  incomplete Hermes support for scrypt; Argon2id is the primary target
