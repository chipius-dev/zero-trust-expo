# ITEM-0039: Document Expo config plugin requirements for native crypto

## Why

Native module configuration in Expo is a common breaking point: missing a config
plugin causes a silent failure at build time that is not caught until App Store
submission. A new team member or a fresh CI runner needs the exact configuration to
reproduce a working build. This story produces that documentation in the repo, not
in a wiki or chat thread.

## Scope

- Survey all native modules introduced by the selected cryptographic library
- For each: Expo config plugin entry, `eas.json` impact, prebuild implications
- Example `app.config.ts` snippet with all required entries
- EAS Build profile requirements
- Notes on managed vs. development build vs. bare workflow distinction

## Out of scope

- CI/CD pipeline implementation — documented separately
- App Store review guidelines compliance
- Performance profiling of native module load time

## Constraints

- Blocked by ITEM-0038 (Hermes compatibility validation must identify what native
  modules are actually required before this story documents them)
- Must produce verified documentation, not theoretical configuration

## Decisions and rejected alternatives

- Chose to write the config documentation as a committed .md file rather than inline
  comments in app.config.ts because inline comments do not appear in the docs index
  and are harder to link from backlog items and ADRs
