# ITEM-0010: Security Testing and Interoperability

## Why

The stated guarantee — that an envelope encrypted on iOS is decryptable on Windows
and vice versa — is not verified by unit tests that run on a single platform. Without
explicit cross-platform interoperability tests, format or encoding divergence between
platforms can remain undetected until production. Without database-compromise tests,
the claim that a stolen database reveals no plaintext is unverified.

## Scope

- Cross-platform interoperability test vectors: fixed test inputs, expected ciphertext
  outputs and decrypted plaintexts, to be run on every target platform
- Tamper detection tests: verify that modifying ciphertext, nonce, or associated data
  causes decryption to fail with an authentication error
- Nonce uniqueness tests: assert that two independent encrypt calls never produce the
  same nonce
- Database compromise test: given a copy of the SQLite schema populated with test data,
  assert that no row contains plaintext passwords, key material, or domain semantics
- Threat model test matrix: per-threat, what the attacker obtains and cannot obtain
- Replay resistance and object-version tampering tests
- Metadata privacy analysis: documented catalogue of unavoidable leakage with mitigations

## Out of scope

- Penetration testing or red-team exercises
- Fuzzing the cryptographic library itself
- Load testing or performance benchmarking
- Third-party security audit (may be commissioned separately)

## Constraints

- Interoperability tests must run in CI on at least two platforms (Node.js and a
  simulated React Native / Hermes environment)
- Test vectors must be committed to the repo and version-controlled

## Decisions and rejected alternatives

- Chose test vectors over live cross-device RPC tests because live cross-device tests
  are fragile in CI; committed vectors are deterministic
- Rejected omitting the database-compromise test because it is the primary claim of
  the zero-trust model; it must be machine-verifiable
