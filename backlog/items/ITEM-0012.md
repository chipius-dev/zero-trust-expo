# ITEM-0012: Research and document cryptographic library candidates

## Why

No cryptographic library has been selected. Proceeding without evidence-based
selection means the architecture may commit to a library that silently lacks Argon2id
on Android, requires a native module on iOS that breaks the managed Expo workflow, or
produces incompatible ciphertext between Web and React Native. The research must be
completed before any implementation begins in ITEM-0003.

## Scope

- Identify candidate libraries: at minimum libsodium.js / libsodium-wasm, @noble/
  (ciphers + hashes + curves), and native WebCrypto API
- For each candidate, verify against all seven target platforms: Web, PWA, iOS,
  Android, macOS, Windows, Linux
- For each candidate, verify against required primitives: Argon2id, XChaCha20-Poly1305,
  X25519, Ed25519, HKDF, CSPRNG
- For each candidate, evaluate: Hermes compatibility, Expo managed workflow, Metro
  bundler, WASM requirements, native module requirements, TypeScript API, security
  audit history, maintenance cadence, CVE history
- Produce a Markdown compatibility matrix committed to docs/architecture/
- Produce a written recommendation identifying the primary library and any required
  shims

## Out of scope

- Writing any implementation code — this is research only
- The ADR itself — that is ITEM-0013 (spike output informs the ADR)
- Performance benchmarking
- Server-side library evaluation

## Constraints

- This is a spike: output is a document, not merged application code
- The compatibility matrix must use verified evidence (test scripts, issue trackers,
  library source code, CI results) not assumptions or marketing copy
- A library may not be marked "supported" on a platform merely because a workaround
  exists in theory

## Decisions and rejected alternatives

- Chose to evaluate @noble/* as a serious candidate alongside libsodium because
  @noble provides pure TypeScript with no WASM dependency, which simplifies Hermes
  and Metro compatibility — but it must be verified for Argon2id support
- Rejected evaluating tweetnacl as the primary candidate because it lacks Argon2id
  and is in maintenance-only mode; it may appear in the matrix as a reference point
- Rejected skipping Hermes compatibility testing because Hermes is the default RN
  engine and WASM support in Hermes is not guaranteed across all RN versions
