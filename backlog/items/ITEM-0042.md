# ITEM-0042: Archive zero-trust backlog and restore clean template state

## Why

A developer who instantiates this template to build a different application should
see an empty backlog dashboard — not 42 pre-existing items from the zero-trust
initiative. Leaving the items in place forces every new user to manually archive
or drop 42 items before they can start their own work, which defeats the purpose
of the template. Archiving as the final step restores the clean state that
`make status` should show on a fresh clone.

## Scope

- Run `make archive ID=ITEM-0042` last (this item archives itself)
- Run `make archive ID=ITEM-XXXX` for every preceding item in reverse-dependency
  order (leaf stories first, then epics, then the initiative)
- Verify `ls backlog/items/` shows only `.gitkeep`
- Run `make status`, `make lint`, `make check` and confirm all are green
- Commit the archive rollup and the empty items directory

## Out of scope

- Deleting the archive file `backlog/archive/2026.md` — it is the historical record
- Removing implementation code, tests, ADRs, or documentation
- Modifying the SDLC tooling or any generated files beyond the backlog state

## Constraints

- This is the last story that can be started; all of ITEM-0001 through ITEM-0040
  must be `done` before this story begins (lint enforces this: a `done` item must be
  archived before the next item in the same file can be archived without error)
- Must use `make archive`, not manual file deletion, to ensure the rollup is correct

## Decisions and rejected alternatives

- Chose archiving every item (including the initiative and epics) rather than leaving
  them open so that `make status` genuinely shows zero open items — a partial archive
  would still pollute the dashboard for new users
- Rejected a helper script that archives all items in one command because the current
  tooling archives one item at a time and that contract is enforced by `make ci`;
  a bulk-archive script would bypass the schema checks
