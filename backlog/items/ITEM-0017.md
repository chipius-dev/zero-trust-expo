# ITEM-0017: Implement secure random byte generation across all platforms

## Why

Nonce generation, salt generation, and key generation all depend on a
cryptographically secure pseudo-random number generator. A polyfill that falls back
to `Math.random` on unsupported platforms silently produces predictable values,
making nonces and salts guessable. Each platform has a different CSPRNG API;
the abstraction must use the correct one without falling through to an insecure source.

## Scope

- Implement `randomBytes(length: number): Uint8Array` for the CryptoProvider
- Platform dispatch: `crypto.getRandomValues` on Web/PWA/Node 19+, the selected
  library's secure random implementation on React Native/Hermes
- Explicit error if the platform CSPRNG is unavailable — no silent fallback
- Tests asserting non-repetition and correct length

## Out of scope

- Nonce management policy (managed by encrypt/decrypt callers)
- UUIDs or other higher-level random structures

## Constraints

- Blocked by ITEM-0014 and ITEM-0013
- Must not use `Math.random` under any code path
- Must work without native modules in the Expo managed workflow

## Decisions and rejected alternatives

- Chose platform-dispatch pattern over library-only dispatch because some platforms
  expose `crypto.getRandomValues` natively and using it avoids a WASM load entirely
- Rejected a single try/catch with `Math.random` fallback because silent fallback to
  an insecure PRNG is worse than a hard failure
