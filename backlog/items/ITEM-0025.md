# ITEM-0025: Implement domain model serialization to encrypted blob pipeline

## Why

The pipeline from domain model to opaque ciphertext has multiple steps where bugs can
silently introduce plaintext leakage or format incompatibilities. Each step must be
independently testable and must follow the specification in ITEM-0024 exactly so that
envelopes produced on one platform can be decrypted on another.

## Scope

- `encryptObject<T>(obj: T, key: CryptoKey, keyVersion: number): Promise<EncryptedEnvelope>`
- `decryptObject<T>(envelope: EncryptedEnvelope, key: CryptoKey): Promise<T>`
- Canonical JSON serialisation (sorted keys, no trailing whitespace)
- Envelope byte layout per ITEM-0024 spec
- Unit and integration tests

## Out of scope

- Compression (reserved but not implemented in this story)
- Attachment/binary blob handling
- Server transport encoding

## Constraints

- Blocked by ITEM-0016 (encrypt/decrypt) and ITEM-0024 (envelope spec)
- Canonical serialisation must be deterministic: same object always produces same bytes

## Decisions and rejected alternatives

- Chose canonical JSON (sorted keys) over `JSON.stringify` default because key
  ordering in JS objects is insertion-dependent and may vary across platforms
- Rejected using protobuf or msgpack for the inner payload because it adds a schema
  dependency; canonical JSON is self-describing and simpler to migrate
