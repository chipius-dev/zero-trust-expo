# ITEM-0034: Implement encrypted sync event log and conflict resolution

## Why

The sync event log is the source of truth for vault state across devices. Without
encrypted event payloads, the server can observe every write: which objects were
updated, when, and how frequently. Without conflict detection, two devices writing
simultaneously silently lose one write. Without an ordered offline queue, a device
that goes offline and reconnects can corrupt vault state by applying writes out of
order.

## Scope

- `appendSyncEvent(objectId, envelope, expectedSequence): Promise<void>`
- Conflict detection: compare returned server sequence against expected, flag conflict
- LWW resolution: discard the local write if the server has a higher sequence number
- Offline queue: persist pending writes locally, replay in order on reconnect
- Replay from sequence 0 for initial device sync

## Out of scope

- WebSocket push events
- Encrypted event log compaction/snapshot (separate story)

## Constraints

- Blocked by ITEM-0033 (protocol design) and ITEM-0029 (sync_events schema)
- Event payloads must be encrypted using the sync key (ITEM-0019)
- Sequence numbers in the sync_events table are the only plaintext per-event field

## Decisions and rejected alternatives

- Chose encrypted event payloads over plaintext event summaries because the server
  must not understand event semantics; a plaintext `updated_field` value leaks domain
- Rejected in-memory-only offline queue because it does not survive app restart
