# ITEM-0029: Define StorageAdapter interface and pipeline types

## Why

The adapter interface is what keeps the template engine-agnostic. Without it, every
feature that needs persistence imports a specific engine directly, making the engine
a hard dependency that users cannot swap. With the interface, the application wires
in its chosen engine at the composition root; all template code depends only on the
abstraction.

## Scope

- `EncryptedBlob`: `{ id: OpaqueId; ciphertext: Uint8Array; keyVersion: number;
  sequenceNumber: number; createdAt: number; updatedAt: number;
  deletedAt: number | null }`
- `StorageAdapter<T extends EncryptedBlob>` interface:
  `put(blob: T): Promise<T>`,
  `get(id: OpaqueId): Promise<T | null>`,
  `delete(id: OpaqueId): Promise<void>`,
  `list(opts: { cursor?: string; sinceSequence?: number }): Promise<{ items: T[]; nextCursor?: string }>`
- `EncodeService<Domain>` interface:
  `encode(obj: Domain, key: CryptoKey, keyVersion: number): Promise<EncryptedBlob>`
  (internally: serialize → compress → AEAD encrypt)
- `DecodeService<Domain>` interface:
  `decode(blob: EncryptedBlob, key: CryptoKey): Promise<Domain>`
  (internally: AEAD decrypt → decompress → deserialize)
- Round-trip integration test asserting decode(encode(x)) deeply equals x

## Out of scope

- Any concrete StorageAdapter implementation (expo-sqlite, MMKV, AsyncStorage,
  remote fetch) — that is the application's responsibility, not the template's
- Compression algorithm selection — the EncodeService reserves the step; the
  algorithm is a downstream implementation detail
- Migration runners or schema versioning

## Constraints

- Blocked by ITEM-0016 (encrypt/decrypt) and ITEM-0025 (domain-to-envelope pipeline)
- No storage engine import in the interface file
- `EncryptedBlob` must not carry any domain-semantic field

## Decisions and rejected alternatives

- Chose a minimal four-method adapter (put/get/delete/list) over a richer query
  interface because any query semantics beyond list-with-cursor require the adapter
  to understand object content, which violates the opaque boundary
- Rejected embedding compression into the EncryptedEnvelope spec because compression
  is an EncodeService implementation detail; the adapter sees only the final
  ciphertext, not the intermediate compressed bytes
