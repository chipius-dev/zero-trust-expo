# ITEM-0014: Define CryptoProvider TypeScript interface and envelope types

## Why

Application code cannot be written until the contract is fixed. The interface file
is the boundary between the application and the crypto implementation; defining it
before the implementation prevents library types leaking into calling code.

## Scope

- `CryptoProvider` interface with: randomBytes, hashPassword, verifyPassword,
  deriveMasterKey, deriveSubkey, encrypt, decrypt
- `EncryptedEnvelope` type: version, algorithm, keyVersion, nonce, ciphertext, tag,
  associatedDataHash
- `PasswordVerifier` opaque type
- `CryptoKey` opaque handle type
- `KeyPurpose` enum
- Exported from a single entry-point with no library types in any exported signature

## Out of scope

- Any implementation of the interface — that is ITEM-0015 through ITEM-0017
- Key metadata persistence schema

## Constraints

- Blocked by ITEM-0013 (ADR must be accepted before the interface is locked in)
- Must compile under TypeScript strict mode
- No concrete library import in the interface file

## Decisions and rejected alternatives

- Chose opaque handle types for CryptoKey over `Uint8Array` because leaking raw key
  bytes in a type signature invites callers to log, serialise, or transmit them
- Rejected using `unknown` for envelope fields because callers need structural access
  to fields like keyVersion for rotation logic without deserialising the ciphertext
