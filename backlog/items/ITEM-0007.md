# ITEM-0007: Storage Adapter and Serialization Contract

## Why

The template must not impose a storage engine. Different applications will choose
expo-sqlite, MMKV, AsyncStorage, a remote API, or a combination. What the template
can and should provide is the abstract boundary between the client UI and whatever
persistence layer the application chooses: a typed adapter interface, and the
encode/decode pipeline that any persistence implementation must honour.

## Scope

- Core domain entity TypeScript interfaces (the client UI's vocabulary)
- API contract request/response types (what crosses the client–server boundary:
  opaque IDs and ciphertext, never plaintext domain content)
- Abstract `StorageAdapter` interface: the contract any persistence implementation
  must satisfy — `put(id, blob)`, `get(id)`, `delete(id)`, `list(cursor)` — typed
  against the encrypted blob shape, not a specific engine
- Encode pipeline service types: domain object → serialize → compress → encrypt →
  `EncryptedBlob` ready to hand to the adapter
- Decode pipeline service types: `EncryptedBlob` from the adapter → decrypt →
  decompress → deserialize → domain object

## Out of scope

- Any specific storage engine (expo-sqlite, MMKV, AsyncStorage, IndexedDB, remote)
- SQL DDL of any kind — server or client
- Query APIs, indexes, or migration runners
- Choosing a compression algorithm (reserved as a pipeline step; algorithm is
  implementation detail downstream of the template)

## Constraints

- The `StorageAdapter` interface must be engine-agnostic: no SQL, no key-value
  semantics beyond put/get/delete/list
- Blocked by ITEM-0005 (auth contract) and ITEM-0006 (encrypted envelope format)
- Encode and decode must be invertible: decode(encode(x)) === x, provable by test

## Decisions and rejected alternatives

- Rejected including expo-sqlite DDL because it would couple the template to one
  storage engine, forcing every user to either adopt it or rip it out
- Rejected a richer query adapter interface (filter, sort) because the server
  is untrusted; the client queries its local copy of decrypted objects, which is
  outside the template's scope
