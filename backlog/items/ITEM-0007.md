# ITEM-0007: Client-Side Data Model and API Contract

## Why

Without a shared vocabulary of TypeScript types, client code invents its own
ad-hoc shapes for what it sends to and receives from the server, and the local
offline store has no stable schema. Divergent shapes across features produce silent
data loss, missed fields on deserialization, and sync protocol bugs that only
manifest on the second device. The client needs: (a) stable domain types for the
encrypted objects it manages locally; (b) typed API contract shapes for every
server interaction; (c) a local expo-sqlite schema for offline operation.

## Scope

- TypeScript interfaces for every entity the client owns: Account, AuthCredential,
  Session, Device, EncryptedObject, ObjectVersion, SyncEvent, Revocation
- API contract request/response types for each server endpoint the client calls
  (these are what the wire carries — opaque IDs and ciphertext, never plaintext
  domain content)
- Client-side expo-sqlite DDL for local offline storage of encrypted blobs,
  sync queue, device state, and tombstones
- Privacy boundary annotation on each API type: what the server receives, what it
  never receives, what the client keeps locally only

## Out of scope

- Server-side database schema or SQL DDL — the server implementation is not
  part of this template
- ORM or query layer code beyond the raw expo-sqlite schema
- Server endpoint implementation or routing logic
- Any schema for server-side relational joins or full-text search

## Constraints

- All types must reflect the zero-trust constraint: no plaintext domain content
  in any server-facing type; only opaque IDs and ciphertext
- Blocked by ITEM-0005 (auth flow design) and ITEM-0006 (envelope format)
- expo-sqlite schema must be additive-migration-compatible from the first version

## Decisions and rejected alternatives

- Chose TypeScript-first (types → client schema) over SQL-first (DDL → types)
  because the client is the authoritative domain owner; the server stores opaque
  blobs and should not dictate the client's model
- Rejected including server SQL DDL because this is an Expo/React Native template;
  server implementation is a separate concern outside the template's scope
