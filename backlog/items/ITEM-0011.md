# ITEM-0011: Expo and React Native Integration

## Why

A cryptographic library that works in Node.js but fails on Hermes, requires ejecting
from the managed Expo workflow, or needs per-platform native module maintenance
invalidates the cross-platform architecture. This epic ensures the selected library
and the CryptoProvider implementation meet the actual constraints of Expo-based
development, CI, and production builds across all seven target platforms.

## Scope

- Validate and document selected library compatibility with Expo managed workflow,
  Expo development builds, and bare workflow
- Hermes engine compatibility verification (WASM loading, BigInt, TextEncoder,
  crypto.getRandomValues polyfills)
- Metro bundler configuration for any WASM assets
- Expo config plugin requirements for any native modules (if unavoidable)
- ESM / CommonJS interop requirements
- Production build requirements: App Store, Google Play, macOS notarisation,
  Windows packaging, Linux distribution
- CI pipeline documentation for cross-platform test execution

## Out of scope

- iOS/Android app UI or navigation setup
- Expo Router and screen architecture
- Push notification plumbing
- OTA update strategy

## Constraints

- Native module usage must be justified and documented; pure JS/WASM preferred
- Blocked by ITEM-0002 (library selection must be confirmed before integration work)
- Must not require users of the template to maintain custom native modules for
  cryptography unless absolutely unavoidable

## Decisions and rejected alternatives

- Rejected assuming that any Node.js-compatible library automatically works on Hermes
  because Hermes has a restricted JS engine feature set; WASM support and engine
  globals must be explicitly verified
- Rejected treating Expo compatibility as a nice-to-have; it is a hard gate
