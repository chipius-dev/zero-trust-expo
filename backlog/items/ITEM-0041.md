# ITEM-0041: Project Close-Out and Template Restoration

## Why

This repository is a reusable template, not a permanent home for the zero-trust
cryptographic architecture backlog. Once all implementation work is complete and
merged, the backlog items serve no purpose in the template's default state — they
become noise for anyone who instantiates the template to build a different project.
The close-out step reverts the repo to the clean, empty-backlog state that a fresh
instantiation should show, while leaving the implementation artifacts (code, ADRs,
docs) intact as the template's example content.

## Scope

- Archive all 41 completed backlog items (ITEM-0001 through ITEM-0041) using
  `make archive` per the documented process
- Confirm `backlog/items/` is empty (only `.gitkeep` remains)
- Confirm `make status` shows 0 open items and the dashboard reads "nothing ready"
- Confirm `make lint` and `make check` remain green after archival

## Out of scope

- Removing the implementation code, ADRs, or documentation produced by the initiative
- Resetting git history
- Modifying the SDLC tooling itself

## Constraints

- Must be the last item executed; it cannot be started until all ITEM-0001 through
  ITEM-0040 are `done` and archived
- Uses only `make archive` — no manual file deletion

## Decisions and rejected alternatives

- Chose archiving over deleting because the archive rollup (backlog/archive/2026.md)
  becomes the template's worked example of a completed initiative, demonstrating the
  full lifecycle to future instantiators
- Rejected a separate "clean slate" script because `make archive` is the documented
  process and using it means CI stays green throughout
